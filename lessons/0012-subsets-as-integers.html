Subsets as Integers

Since lesson 0001, the constraint n ≤ 20 has meant one thing: exponential is allowed. This lesson cashes that in. A subset of 20 items is a 20-bit number, so “try every subset” becomes “count from 0 to 220” — and the one trick that stops a factorial from killing you at the same n.

The tell is the tiny bound. Every other lesson read a large n and eliminated slow families. Here a small n is the signal: nobody sets n ≤ 20 on a problem with a clever linear solution. They set it because the intended solution looks at every subset — 220 ≈ 106 — and the bound is there to keep that honest.

The question

You have n apples with known weights. Split them into two groups so the difference between the group weights is as small as possible, with 1 ≤ n ≤ 20 and weights up to 109. This is CSES 1623, Apple Division . Weights to 109 rule out any table indexed by weight, so the knapsack-style DP is gone; the bound on n is the only thing left to read.

Say this before touching a tiny-n problem

Each item is in or out, so there are 2n choices, and 220 is about a million — affordable. If the problem instead asks for an order, it's n!, and 20! is about 2.4×1018 — not affordable. Same n, a trillion-fold different cost. Which one am I being asked for?

A subset is an integer

Number the items 0 to n−1. Let bit i of an integer be 1 if item i is in the subset. Then every integer from 0 to 2n−1 is exactly one subset — called a mask — and range(1 << n) visits all of them. Three operations are the whole vocabulary:

mask >> i & 1        # is item i in the subset?   (shift it down, read the last bit)
mask | 1 << i        # add item i
mask & -mask         # isolate the lowest set bit (used below)

Apple Division, directly:

def apple_division(p):
    n, total = len(p), sum(p)
    s = [0] * (1 << n)                    # s[mask] = weight of that subset
    best = total
    for mask in range(1, 1 << n):
        low = mask & -mask                 # lowest item in the subset
        s[mask] = s[mask ^ low] + p[low.bit_length() - 1]
        best = min(best, abs(total - 2 * s[mask]))
    return best

The middle line is the lesson-0007 move in miniature: the weight of a subset is the weight of the same subset without its lowest item, plus that item. Each mask is computed from a smaller mask in O(1), so the whole loop is O(2n) instead of O(2n·n). The USACO Guide's bitmask DP page uses the same encoding and notes that its own Python solution to the harder problem below times out — Python's constant factor is the real enemy at this bound.

When the answer is an order

Suppose the problem were instead: visit every city exactly once, minimising total travel, with n ≤ 20. Brute force over orders is 20! — dead. But look at what actually matters about a half-finished route: which cities are done (a mask) and where you are now. Two different orders that visit the same set and end at the same city have the same future. So define dp[mask][last] and the USACO Guide's statement of it is exactly that: “the number of routes that visit all the cities in the subset S and end at city i.” Cost: 2n·n² — about 4×108 at n=20, heavy for Python but the right shape, versus 1018.

That is lesson 0007 again: the mask is the state, and it works because many paths collapse onto one state. You don't need to write the TSP solution today. You need to hear “order, n ≤ 20” and answer “mask plus last element” instead of “permutations”.

The bug that passes the sample. Writing mask & i instead of mask >> i & 1 reads “is item i in the set” as a bitwise AND with the index itself. It runs, returns plausible numbers, and on 3,000 random small inputs it disagreed with a brute-force check on 39.0% of them. The correct version, and the incremental one, agreed on all 3,000. (Python precedence also bites: 1 << n - 1 parses as 1 << (n-1), half the masks. Always bracket: (1 << n) - 1.)

Saying it out loud

"n is at most 20, which is a deliberate bound - nobody sets that for
 a linear solution. Weights go to 1e9, so no weight-indexed table.
 Each apple is in one group or the other: 2^20, about a million
 subsets, fine. I'll encode a subset as a bitmask and build each
 subset's weight from the same subset minus its lowest bit, so the
 per-mask cost is O(1) - re-summing would be 20 million steps, which
 is tight in Python.

 If the problem asked for an order instead, that's 20 factorial,
 so I'd switch to dp over (mask of visited, last visited)."
