One Node Per Prefix

Some problems hand you a fixed dictionary of words and then ask, again and again, “does anything start with this?” Scanning every word per question rereads the same leading letters over and over. A trie stores each distinct prefix exactly once, so a question costs the length of the prefix asked about — not the size of the dictionary.

The tell is many queries about prefixes of a fixed set of strings — autocomplete, “implement startsWith,” “add and search words,” “find all words from a dictionary on a board.” If instead you are searching for one pattern inside one long text, that is a different family (substring search), not this one. If the words are few and the queries are few, a plain loop is fine — check the budget with lesson 0001 first.

The repeated-scan version

Implement Trie (LeetCode 208): insert words, then answer search(word) (is this exact word present?) and starts_with(prefix) (does any word begin with this?). With a list, each query is a loop over every word: with 5,000 words and 2,000 prefix queries that is up to 10,000,000 word checks, and every check re-compares the same first letters that the previous check already compared.

A tree where a path spells a prefix

Make one node per distinct prefix. A node maps each next letter to a child, and carries a flag saying whether a word ends here. In the words of cp-algorithms: “a trie is a rooted tree, where each edge of the tree is labeled with some letter and outgoing edges of a vertex have distinct labels,” and each vertex is identified with the string spelled on the path from the root. This is a tree in lesson 0008's sense: every node has exactly one parent, so there is no visited set to keep (contrast lesson 0015).

class Trie:
    def __init__(self):
        self.kids = {}               # next letter -> child Trie
        self.end = False             # does a word finish exactly here?

    def insert(self, word):
        node = self
        for c in word:
            node = node.kids.setdefault(c, Trie())
        node.end = True

    def _walk(self, s):              # follow s from the root, or None if it falls off
        node = self
        for c in s:
            node = node.kids.get(c)
            if node is None:
                return None
        return node

    def search(self, word):
        node = self._walk(word)
        return node is not None and node.end

    def starts_with(self, prefix):
        return self._walk(prefix) is not None

Each operation touches one node per letter, so it costs O(L) for a string of length L, whatever the dictionary size. cp-algorithms gives the memory side: with an array of k links per vertex it uses “O(m k) memory” (m is the total length of all words, k the alphabet size), and with a map per vertex “O(m)” at the price of a log k factor. The dict above is the map version.

Say this before writing a trie

Is the dictionary fixed while prefix questions pile up? If so: one node per prefix, a path per word, and an end flag. search and starts_with are the same walk — they differ only in what they check at the last node.

The one-line bug: forgetting the end flag. If search returns just self._walk(word) is not None, it looks right and is fast, but it answers starts_with. After inserting apple, it claims app is a word. Measured on 20,000 random dictionaries of 0–6 short words over {a, b}, with 5 random queries each, the flagless search was wrong on 14,614 of 100,000 queries (14.6%); the correct one on 0.

Checked against a slower, honest reference

search and starts_with were compared with q in words and any(w.startswith(q)) on the same 100,000 random queries. 0 of 100,000 disagreed. (A first run showed 2,372 disagreements; they were all the empty prefix against an empty dictionary, where the trie's root exists but no word does — a test-harness edge, not a trie bug, and worth knowing if a problem allows empty prefixes.)

Saying it out loud

"Fixed dictionary, lots of prefix questions - rescanning the word list
 per query is words x queries, too slow at 1e5 each.

 I build a trie: one node per distinct prefix, each node maps the next
 letter to a child, plus a flag for 'a word ends here'. Insert walks
 and creates as needed; a query walks and stops if it falls off.

 starts_with is 'did the walk survive'. search is 'did it survive AND
 is the end flag set'. Both are O(length of the string), independent
 of how many words there are. Memory is O(total letters) with a dict
 per node, times alphabet size with arrays."
