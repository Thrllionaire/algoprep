Settle Each Node Once

Lesson 0008 traversed trees, where every node has exactly one path down from the root, so the recursion could never double back. A general graph makes no such promise: cycles and shared neighbours mean many paths can reach the same node. The fix is one extra piece of state — a visited set, marked the moment a node is discovered — and getting its timing right is the whole lesson.

The tell is an adjacency list (or matrix) plus a question about reachability, connectivity, or the fewest edges between two nodes. “Fewest edges,” not “cheapest route” — the moment edges carry different costs, this lesson's BFS is the wrong tool and you want Dijkstra instead, which is out of scope here. Grids count: a 2D grid where you move to the four neighbours is a graph with at most four edges per node, just drawn as a rectangle instead of a diagram.

Why the tree recursion breaks

Lesson 0008's DFS visited every child with no bookkeeping, because a tree guarantees the recursion can never revisit a node — there is exactly one path from the root to anywhere. Paste that same code onto a graph with a cycle and it stops being safe:

def dfs_no_visited(node, adj):
    for neighbour in adj[node]:
        dfs_no_visited(neighbour, adj)   # copied straight from the tree version

# a three-node triangle: 0-1, 1-2, 2-0
adj = {0: [1], 1: [0, 2], 2: [1, 0]}
dfs_no_visited(0, adj)

On that three-node triangle, the call above never returns: 0 calls 1, 1 calls 0, 0 calls 1, forever. Measured with sys.setrecursionlimit(2000), it raises RecursionError at exactly the 2,000th call — three nodes and three edges are enough to exhaust any recursion limit you set. A tree has no back edges to loop on; a graph can have any number of them.

The fix: mark a node the moment you find it

Breadth-first search explores the graph one layer at a time, using a queue instead of recursion. The visited set is what keeps every node from being processed more than once:

from collections import deque

def bfs_shortest_path(adj, start):
    dist = {start: 0}
    queue = deque([start])
    while queue:
        u = queue.popleft()
        for v in adj[u]:
            if v not in dist:          # mark the instant it is discovered
                dist[v] = dist[u] + 1
                queue.append(v)
    return dist

dist doubles as the visited set here — a node is marked the moment it is discovered, when it is appended to the queue, not when it is later popped. Because BFS explores in strict layers — every node at distance k is queued before any node at distance k+1 — the first time a node is discovered is guaranteed to be by the shortest possible path. The USACO Guide states the traversal order plainly: “In a breadth-first search, we travel through the vertices in order of their distance from the starting vertex,” and the same page notes what the visited bookkeeping buys both BFS and DFS: “The algorithm keeps track of visited nodes, so that it processes each node only once.” DFS needs the identical set for the identical reason — it answers reachable or not and how many separate components rather than fewest edges, but it still loops forever without one, exactly as above.

Say this before writing a graph traversal

Can this graph revisit a node — does it have a cycle, or can two edges lead to the same place? If so, I need a visited set, marked at discovery. Does the question want fewest edges (BFS) or just reachable-or-not / how-many-components (BFS or DFS, either works)? And am I marking visited when I find a node, or only when I finish processing it?

The bug that still terminates. A tempting shortcut: check visited only when a node is popped, not when it is pushed. It still terminates and still returns the right distances — so it passes a quick test — but the same node can sit in the queue many times before its first pop marks it. On a 26-node, 105-edge layered graph (five layers of five nodes, each layer fully connected to the next), the correct version does exactly 26 pushes, one per node. Marking at pop instead of push does 106 — a 4× blow-up from one timing change, and it gets worse as the layers widen, because every one of a layer's nodes re-pushes every node in the next layer before any of them is marked.

Checked against a slower, honest reference

bfs_shortest_path was run against 2,000 random graphs of 2–9 nodes and compared to a brute-force shortest-path routine (repeatedly relaxing every edge until nothing changes — slow, but not a BFS, so it cannot share a bug with it). 0 of 2,000 disagreed.

Saying it out loud

"Adjacency list, fewest edges between two nodes, every edge the same
 weight - that's BFS. I need a visited set because this graph can have
 cycles, unlike the trees in lesson 0008 - a node can be reached more
 than once, so something has to remember it already has been.

 I mark a node visited the moment I push it onto the queue, not when
 I pop it - otherwise several already-queued nodes can all push the
 same neighbour before any of them marks it, and I do extra work for
 no extra correctness.

 BFS finds the shortest route first because it empties one whole layer
 of distance k before starting layer k+1 - a shorter route would have
 belonged to an earlier layer and would have gotten there first."
