The Border You Already Matched

Lesson 0022 found a pattern in a text by fingerprinting every window, with randomness and a confirmation step. KMP gets the same O(n + m) with no randomness: when a mismatch happens, it does not re-read the characters it already matched. It keeps the longest stretch that is still alive, and a single array, the prefix function, says how long that stretch is.

The tell is exact matching where hashing is unwelcome — an adversarial judge, a demand for a deterministic bound, or a question about the pattern itself: its repeating period, its longest prefix that is also a suffix. Rule it out when matching is approximate (edit distance, lesson 0020) or when many words share prefixes (a trie, lesson 0019).

The question

Same as lesson 0022: every position where a pattern occurs in a text. Comparing the pattern against each window character by character costs, on a text of 100,000 as and a pattern of 49,999 as then a b, (n − m + 1) · m = 2,500,050,000 comparisons. The code below does the same job reading 150,001 characters, with 99,999 fallback steps in total.

One array: how much of the pattern is still alive

A border of a string is a proper prefix that is also a suffix. (“Proper” means shorter than the whole string.) The prefix function is the table of the longest border at each position. In cp-algorithms’ words, “π[i] is the length of the longest proper prefix of the substring s[0…i] which is also a suffix of this substring.” By hand, for abcabca:

i0123456
s[i]abcabca
π[i]0001234

π[6] = 4 because abca is both the first four and the last four characters. Why this helps: if you have matched k characters of the pattern and the next text character disagrees, then the last k text characters are the first k pattern characters, so the longest part of that which can still be a pattern prefix is exactly the longest border of the matched part: π[k−1]. Fall back to it and compare again. The text position never moves backward.

def prefix_function(s):
    pi = [0] * len(s)
    k = 0                                    # length of the border still alive
    for i in range(1, len(s)):
        while k and s[i] != s[k]:
            k = pi[k - 1]                    # fall back to the next-longest border
        if s[i] == s[k]:
            k += 1
        pi[i] = k
    return pi

def find_all(text, pat):
    if not pat or len(pat) > len(text):
        return []
    m = len(pat)
    pi = prefix_function(pat + "#" + text)   # "#" appears in neither string
    return [i - 2 * m for i in range(m + 1, len(pi)) if pi[i] == m]

Gluing pat + "#" + text is cp-algorithms’ own trick: “We generate the string s + # + t, where # is a separator that appears neither in s nor in t.” Any position where π equals the pattern length is a match ending there. The cost is the amortisation from lesson 0003: the border length k rises by at most one per character (“the values of the prefix function can only increase by at most one”), and each fallback lowers it, so fallbacks in total never exceed the increases. O(n + m) time, and the quote’s memory claim is “O(n) memory”.

Say this before writing the loop

Window-by-window comparison is O(n·m). On a mismatch after k matched characters, those k text characters equal the pattern’s first k, so I keep the longest border of that prefix, π[k−1], instead of restarting. Border length rises at most one per step, so fallbacks are amortised and the whole thing is O(n + m), deterministic. I join pattern, a separator and text so one pass computes everything.

Three ways to get it wrong, measured on 20,000 random small cases (text length 1–14, pattern length 1–5, alphabets of 2–3 letters) against a brute-force search. (1) Dropping the separator (pat + text) disagrees on 3,234 (16.2%): a border can then run across the boundary and read as a match. (2) Falling back by k -= 1 instead of k = pi[k-1] disagrees on 2,537 (12.7%): it tries a shorter prefix, not the longest border. (3) A text scan that resets k to 0 on a mismatch disagrees on 269 (1.3%) — rare on random input, which is why it survives casual testing. The code above scored 0.

The same array answers questions about the string itself

If the whole string has longest border L, its smallest period is p = n − L, and the string is made of repeated blocks exactly when L > 0 and p divides n. That is the whole of LeetCode 459 in four lines. Checked against a brute-force “does some block repeat to give s” on 20,000 random binary strings: 0 disagreements. Hashing cannot answer this without testing every divisor.
