Cheapest First

Lesson 0015's BFS settles nodes in order of edge count. Once edges carry costs, the order that matters is total cost — and a min-heap from lesson 0009 hands you the cheapest unsettled node every time. That pairing is Dijkstra's algorithm.

The tell is “shortest” or “cheapest” over a graph whose edges have different non-negative costs — travel times, prices, delays. Equal costs mean plain BFS; negative costs mean Dijkstra is the wrong tool. Constraints like V, E ≤ 105 (lesson 0001) point at O(E log V), which is exactly its cost.

The question

Network Delay Time (LeetCode 743): signals travel along directed edges (u, v, w) taking w units; starting at node k, how long until every node has the signal? That is the largest of the shortest distances from k. The definition, from cp-algorithms: “The weights of all edges are non-negative.”

Why BFS stops being enough

BFS finds a node first along the path with the fewest edges, and lesson 0015 settled it at that moment. With costs, the fewest-edges path need not be the cheapest: a direct edge costing 9 loses to two edges costing 1 and 2. So the settling rule changes from “first reached” to “cheapest reached, among everything not yet settled.” The source states the invariant: “After any vertex v becomes marked, the current distance to it d[v] is the shortest, and will no longer change.” It holds because every remaining path to v must pass through some unsettled node that is already at least as costly, and adding a non-negative edge cannot make it cheaper.

import heapq

def dijkstra(n, adj, source):
    dist = [float('inf')] * n
    dist[source] = 0
    heap = [(0, source)]                    # (cost so far, node)
    while heap:
        d, u = heapq.heappop(heap)          # cheapest unsettled entry
        if d > dist[u]:                     # stale: a cheaper route to u was already found
            continue
        for v, w in adj[u]:
            if d + w < dist[v]:
                dist[v] = d + w
                heapq.heappush(heap, (d + w, v))
    return dist

def network_delay_time(times, n, k):
    adj = [[] for _ in range(n)]
    for u, v, w in times:
        adj[u - 1].append((v - 1, w))
    dist = dijkstra(n, adj, k - 1)
    worst = max(dist)
    return -1 if worst == float('inf') else worst

A node can be pushed several times, each time with a lower cost; the heap pops the cheapest entry first, so older, costlier copies surface later as stale and are skipped. The USACO Guide's note on this: “It's important to include continue. This ensures that when all edge weights are non-negative, we will never go through the adjacency list of any vertex more than once.” Cost: “O(N+M log N)” in their implementation, written O(E log V) in interview shorthand.

Say this before writing the loop

Shortest path, edges have different non-negative costs, so BFS is out. I'll keep a min-heap of (cost, node); pop the cheapest, skip it if stale, relax its edges, push any improvement. Settling happens when a node is popped, not when it is pushed.

Two tempting wrong versions. (1) Run lesson 0015's BFS and add the weights along the way: it settles each node on its first arrival. (2) Keep the heap but mark a node settled when you push it, as BFS does with its queue. Both fix a node's distance before a cheaper route can arrive. Measured on 20,000 random small directed graphs (2–7 nodes, weights 1–9) against Bellman-Ford: BFS-with-weights wrong on 4,006 (20.0%), mark-on-push wrong on 3,916 (19.6%), and the code above on 0.

What the stale check buys

Dropping the if d > dist[u]: continue line leaves the answers correct but the work inflated. On a 400-node graph with an edge from every node to every later node (79,800 edges), the version with the check scans 79,801 edges in total; without it, 10,587,199. The line is a performance guard, not a correctness one — which is exactly why it gets forgotten.

Saying it out loud

"Shortest path with varying non-negative edge costs, 10^5 nodes.
 BFS counts edges, not cost, so it's out; negative edges would rule
 Dijkstra out too, and there are none.

 Min-heap of (cost, node). Pop the cheapest. If its cost is above the
 recorded distance it's stale, skip it. Otherwise relax each edge: if
 cost-plus-weight beats the neighbour's distance, record it and push.
 A node is final when popped, not when pushed.

 Each edge pushes at most once, so O(E log V). Answer here is the max
 distance, or -1 if any node is still infinite. If every edge cost 1
 I'd just use BFS."
