Algorithm Intuition

Mission: Algorithm Problem Intuition for Staff+ Interviews

Why

Naren is interviewing for Staff Engineer+ software roles within the next 4–6 weeks and has not done grind-style algorithm practice before. The bottleneck is not coding ability — it is pattern selection: looking at an unfamiliar problem and knowing, within the first two minutes, which family of techniques it belongs to. Without that, every problem becomes a from-scratch research project on a 45-minute clock.

Success looks like

  • Reading a problem statement cold and naming the two or three candidate techniques out loud, with the reason, before writing any code.
  • Using the input constraints to eliminate whole families of approaches before thinking about the problem itself.
  • Knowing the invariant of each core pattern well enough to get the details right first time (the window-shrink condition, the DP recurrence, the loop bound).
  • Narrating that reasoning to an interviewer as trade-off analysis — the Staff+ signal — rather than silently pattern-matching.

Constraints

  • Hard deadline: interviewing within ~4–6 weeks (mission written 2026-09-26, so target window ≈ late October / early November 2026).
  • Python for all code. Short, idiomatic, no library exotica.
  • New to LeetCode-style practice, so patterns need introducing, not just sharpening.
  • Urgency means we optimise for recognition coverage over depth. Breadth of correct triage beats mastery of three patterns.
  • Lessons must be short enough to fit in a working session and be revisited later.

Out of scope

  • System design and behavioural rounds (separate prep track).
  • Competitive-programming exotica with no interview presence: heavy-light decomposition, suffix automata, flow algorithms.
  • Language trivia and Python internals.
