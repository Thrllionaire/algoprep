The Prefix Pair

A subarray is a pair of boundaries, and its sum is their difference. Pick what to accumulate, and the partner you look up falls out of one subtraction.

The identity

p[0] = 0                      # p has n + 1 entries, not n
p[k] = arr[0] + ... + arr[k-1]

sum(arr[l..r]) = p[r+1] - p[l]

There are n + 1 boundaries and every subarray is exactly one pair i < j, namely arr[i..j-1]. Choosing 2 from n + 1 gives n(n+1)/2, which is the subarray count you already expect.

The reframe

Every question about a subarray is a question about two boundary values. Restate the problem that way before choosing machinery.

What to do with the pair

Rows one and two are O(n) and are the interview answers. Row three is the one to name, and then only reach for if the problem insists.

Choosing the key

The sweep never cared that the running value was a sum. It cared that the property you want is a difference of two boundary values. Find that statistic and everything else is unchanged.

When the property is "nothing changed between the boundaries" — divisible, balanced, all even — the difference is zero, so the partner is p[j] itself and the question becomes "have I been in this state before?"

The four templates

Count them

from collections import Counter

def count_sum_x(nums, x):
    seen = Counter({0: 1})
    run = total = 0
    for v in nums:
        run += v
        total += seen[run - x]
        seen[run] += 1
    return total

Longest of them

def longest_sum_x(nums, x):
    first = {0: 0}      # value -> earliest j
    run = best = 0
    for j, v in enumerate(nums, 1):
        run += v
        if run - x in first:
            best = max(best, j - first[run - x])
        if run not in first:
            first[run] = j
    return best

Divisible by k

def count_div_k(nums, k):
    seen = Counter({0: 1})
    run = total = 0
    for v in nums:
        run = (run + v) % k
        total += seen[run]
        seen[run] += 1
    return total

Maximum sum (Kadane)

def max_subarray(nums):
    lowest = run = 0
    best = float('-inf')
    for v in nums:
        run += v
        best = max(best, run - lowest)
        lowest = min(lowest, run)
    return best

The four silent bugs

None of these raises. Each returns a plausible number, and the first two are wrong by small amounts on inputs that look fine.
BugSymptomFix
Map not seeded with {0: 1} Answer slightly low; misses every subarray starting at index 0 Counter({0: 1})
Inserting before counting Correct for every x except 0, where each position counts an empty subarray Count, then insert
p[r] instead of p[r+1] Answer shifted by one element; often survives a small hand-check Keep the p[0]=0, n+1-entry convention
Overwriting in the longest map Finds a valid subarray, but not the longest one Record each value only the first time

Window or prefix pair

When both are legal, the prefix map fails by being heavier and the window fails by being wrong. Prefer the one whose failure mode you can see.
Sliding windowPrefix pair
NeedsA monotonic predicateNothing; the identity always holds
Negative valuesIllegalFine
Natural questionAt most / at leastExactly
Extra spaceO(1)O(n)
Fails byBeing wrong, silentlyBeing heavier than needed

"Exactly" does not automatically forbid a window. With strictly positive values the sum strictly decreases as left advances, so at most one start hits x and one pointer can sit on it (CSES 1660). Distinct-character counts plateau, so several starts tie and the valid band is genuinely wide. The rule is "a band wider than one needs two pointers, and you only have one" — not "exactly is banned".

Not this tool

  • Values change between queries. Prefix sums are static. Use a Fenwick or segment tree.
  • Non-invertible operation. Sum and XOR subtract cleanly; min and max do not. Sparse table or deque instead.
  • "At most" with negatives. Needs a sorted structure over the prefixes, O(n log n), not a hash map.
  • Range updates, point queries. That is a difference array — the inverse construction, and worth knowing it exists.

Say it before you code

"Contiguous shape asking for a count, n is 2e5, so O(n).

 Values can be negative, so a window isn't licensed — removing an
 element can raise the sum and the shrink step repairs nothing.

 So: boundaries, not subarrays. n+1 of them, a subarray is a pair,
 its sum is their difference. I want pairs differing by x, so at
 each j I look up p[j] - x in a map of what I've seen. Seeded with
 {0: 1}, and I count before inserting so nothing pairs with itself.

 O(n) time, O(n) space, sign-agnostic."
