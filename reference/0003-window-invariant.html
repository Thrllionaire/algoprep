Window Invariants

Write the sentence, and the loop writes itself. The shrink condition is the invariant being false; the update goes where the invariant is true.

The skeleton, and its four blanks

left = 0
for right in range(n):
    include(arr[right])       # 1. state the window carries
    while ???:                # 2. the invariant is false
        exclude(arr[left])    # 3. undo an inclusion
        left += 1
    ???                       # 4. the answer update
Blanks 1 and 3 are mechanical: whatever you add you must be able to subtract. Blanks 2 and 4 both come out of one sentence.
BlankDecided byUsual bug
1 · includeWhat the predicate reads tracking the sum when the predicate wants distinct counts
2 · whileThe invariant, negated >= where the problem says "at most", so >
3 · excludeThe inverse of include leaving a zero-count key in the map, so len() lies
4 · updateLongest vs. shortest vs. count measuring inside the shrink loop for a longest window

The invariant sentence

Write it about the line after the shrink loop, before writing any loop:

"When control reaches the update, [left, right] is the LONGEST
 window ending at right that satisfies P."

The shrink loop exists to restore that claim after growing broke it. So the while condition is exactly "the claim is false" — never something to recall. It is a while and not an if because it runs until the claim is true again, which may be many steps in one turn.

The inversion: longest vs. shortest

Longest — shrink to repair

def longest_k_distinct(s, k):
    count = defaultdict(int)
    left = best = 0
    for right, ch in enumerate(s):
        count[ch] += 1
        while len(count) > k:      # INVALID
            count[s[left]] -= 1
            if count[s[left]] == 0:
                del count[s[left]]
            left += 1
        best = max(best,
                   right - left + 1)
    return best

Shrink while broken. Measure after the loop, the only line where the window is known valid.

Shortest — shrink to search

def shortest_at_least(nums, target):
    left = total = 0                # positives
    best = float('inf')
    for right, v in enumerate(nums):
        total += v
        while total >= target:     # VALID
            best = min(best,
                       right - left + 1)
            total -= nums[left]
            left += 1
    return 0 if best == float('inf') \
             else best

Shrink while working. Measure inside the loop: the last size that worked is the smallest one.

Why right - left + 1 counts. With the invariant restored, every window ending at right and starting anywhere in [left, right] is valid, and nothing starting earlier is. Each valid window is counted once, at its own right endpoint. This assumes validity is downward closed — every sub-window of a valid window is valid. True for at most k; false for at least k, where you count the complement and subtract from n(n+1)/2.

Exactly k, by subtraction rather than a cleverer loop, since the predicate is not monotonic in window length:

exactly(k) = at_most(k) - at_most(k - 1)     # guard at_most to return 0 when k < 0

The complexity answer

Count the pointer over the whole run, not the inner loop per iteration. left starts at 0, only increases, stops at n — so at most n shrink steps in total, however unevenly they clump. Two pointers, n moves each, O(n).

"While there is no useful upper bound on how many steps the pointer can move on a single turn, we know that the pointer moves a total of O(n) steps during the algorithm, because it only moves to the right." — Laaksonen, Competitive Programmer's Handbook, ch. 8 (Amortized analysis)

When the window is the wrong tool

Run this first, before the invariant. A window is only licensed when the predicate is monotonic: grow the window and, once the predicate turns false, it must stay false. Two questions — (1) what is my predicate, as one expression over the window's state? (2) if growing the window makes it false, can growing it further make it true again? A yes to the second means no window. Tells: mixed-sign sums, and the word exactly.

Say it before you code

"Contiguous shape, asking for a longest, predicate only tightens as
 the window grows — so a window is valid.

 Invariant: at the update line, [left, right] is the longest window
 ending at right with at most k distinct. So the while condition is
 'more than k distinct', and the update goes after the loop.

 Still O(n): left only moves forward, at most n shrink steps total."
