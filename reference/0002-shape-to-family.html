Read the rows, not the cells. Across a row the machinery barely changes — the return type usually alters only bookkeeping. The one cell that is genuinely different from its neighbours is contiguous + count, which is why it gets its own section below.

The window-vs-prefix-sum rule

A two-pointer sweep is valid only when "movement in one direction should not reverse the effects of movement in the other direction." — USACO Guide

Use a sliding window when the predicate only ever tightens as the window grows — "at most k", "no more than two distinct", "contains all of t". Growing can only break it; shrinking can only fix it. Values non-negative.

Use prefix sums + a hash map when you need an exact value, or when values may be negative. The identity sum(l..r) = p[r] − p[l−1] is sign-agnostic, and nothing ever shrinks, so there is no invariant to break.

The failure is silent. Choosing a window where prefix sums were needed yields wrong answers, not slow ones. Minimum counterexample worth memorising: nums = [1, -1, 0], k = 0. The whole array sums to 0 so the longest run is 3, but a window shrinks past index 0 when the sum first exceeds k and can never return for it, reporting 2.

Kadane is the same sweep. Maximum subarray sum = for each r, p[r] minus the smallest prefix seen before it. Track a running minimum. (USACO Guide)

The two templates

# Contiguous + optimum, monotonic predicate, values positive.  O(n)
def longest_at_most(nums, k):
    left = total = best = 0
    for right, v in enumerate(nums):
        total += v
        while total > k:               # safe: every removal lowers total
            total -= nums[left]
            left += 1
        best = max(best, right - left + 1)
    return best
# Contiguous + exact count, negatives allowed.  O(n)
from collections import defaultdict

def count_exactly(nums, k):
    seen = defaultdict(int)
    seen[0] = 1                        # the empty prefix
    running = count = 0
    for v in nums:
        running += v
        count += seen[running - k]     # earlier prefixes p with running - p == k
        seen[running] += 1
    return count

Limits of this card. The shape is not always stated — "pick some items" needs a clarifying question about whether order matters. Greedy cuts across every cell and is a proof obligation rather than a shape. And these counts assume the shape ranges over the whole input; extra structure (already sorted, bounded values, a tree) can beat them.
