Tree Recursion

The recursion is the data structure, so the pattern is free. Two questions cost you the problem instead: which direction the information moves, and whether what you return is what you were asked for.

The two questions, before any code

Ask in this order

1. Above or below? If the answer at a node depends on what is above it, pass it down as a parameter and do the work before the loop (pre-order). If it depends on what is below it, return it up and do the work after the loop (post-order).

2. Is what I return what I was asked for? Often not. Then return what the parent can use and record the asked-for answer in a variable off to the side.

The three skeletons

# adjacency list, undirected: carry the parent and skip it.
# a tree has no cycles, so this is all the visited-tracking needed.

# 1. POST-ORDER — the answer comes from below, in return values
def f(node, parent):
    acc = base
    for kid in adj[node]:
        if kid != parent:
            acc = combine(acc, f(kid, node))
    return acc                       # work AFTER the loop

# 2. PRE-ORDER — the answer comes from above, in parameters
def g(node, parent, carried):
    out[node] = carried              # work BEFORE the loop
    for kid in adj[node]:
        if kid != parent:
            g(kid, node, extend(carried))

# 3. RETURN ONE, RECORD THE OTHER — the answer turns around at a node
def h(root):
    best = base
    def walk(node, parent):
        nonlocal best
        kids = [walk(kid, node) for kid in adj[node] if kid != parent]
        best = max(best, joins(kids))    # record: turns around here
        return extend_best(kids)         # return: what a parent can extend
    walk(root, None)
    return best

Diameter, the two named quantities

Root the tree arbitrarily. "Every path in a rooted tree has a highest point: the highest node that belongs to the path" (CPH, ch. 14), so it is enough to find the best path at each possible highest point.

Return this

toLeaf(x)
# longest path from x
# DOWN to some leaf
max(tops, default=0)

The only thing a parent can extend by one edge.

Record this

maxLength(x)
# longest path whose
# HIGHEST POINT is x
sum(two largest tops)

The answer. It cannot go upward — it already turned around.

def diameter(root):
    best = 0
    def to_leaf(node, parent):
        nonlocal best
        tops = sorted((1 + to_leaf(k, node) for k in adj[node] if k != parent),
                      reverse=True)
        best = max(best, sum(tops[:2]))    # record
        return max(tops[:1], default=0)    # return
    to_leaf(root, None)
    return best

Returning sum(tops[:2]) instead — the asked-for number rather than the parent's number — runs, terminates, stays O(n), and is wrong on 81.2% of random trees, always too large. It is wrong on 0% of paths and 0% of stars, which is why hand-testing misses it: with one child, the two quantities coincide.

The depth tell

Python's stack limit is 1000 by default: "the maximum depth of the Python interpreter stack … this limit prevents infinite recursion from causing an overflow of the C stack and crashing Python." (Python docs) A tree of n nodes is allowed to be one path of n nodes.

import sys
sys.setrecursionlimit(300_000)   # measured: a 200,000-node path then works
                                 # measured: 999-node path is fine at the
                                 # default, 1000 raises RecursionError

The docs' own warning applies: "the highest possible limit is platform-dependent … this should be done with care, because a too-high limit can lead to a crash." On a hostile bound, or when asked, convert to an explicit stack instead. Say the tell out loud either way — on a tree problem, n ≤ 2·105 is a statement about depth, not only about time.

Saying it out loud

"It's a tree, so the recursion is handed to me and the state is
 just the node. The information I need comes from below, so it
 travels in return values and the work goes after the loop.

 What I return isn't what I was asked for: the parent can only
 extend one downward branch, so that's the return value, and the
 answer that turns around here goes into a running best.

 Adjacency list, so I pass the parent down and skip it. And n is
 2e5 with no balance promise, so a path input is 200k frames deep
 against a limit of 1000 - I'd raise the limit or go iterative."
